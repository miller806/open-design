# OpenDesign 个人版

状态：已实施本地代理入口、云功能停用边界与遥测禁用；旧云模块的物理删除和完整生成验收仍未完成。

## 目标与范围

在现有 OpenDesign 上保留原有设计效果和原型工作流，作为单人本地设计工具。
优先使用已安装的本地代理 CLI（例如 Codex、Claude Code），保留自定义模型 API
作为备用。官方账号不得成为创建、编辑、保存、恢复或导出项目的前提。

保留：设计体系、模板、技能、原型生成、HTML 编辑、预览、历史记录、本地导出、
本地文件访问、自有 API、本地代理接入，以及本地服务和文件访问的安全边界。

移除：官方账号和登录、官方云模型 AMR/Vela、余额/充值/订阅、团队/邀请、
云同步、公开分享，以及官方使用指标和内容遥测。

其他功能（如自动化、连接器、宠物、媒体生成）暂不视为获准删除范围；
先完成上述明确范围，避免连带破坏技能和设计模板。

## 已核对的代码边界

- `apps/web/src/App.tsx`：主界面直接使用官方登录状态、AMR 模型目录、
  工作区计费状态和余额门禁。需要解除初始化、模型选择和项目操作的云依赖，
  不能仅隐藏账号按钮。
- `apps/web/src/state/config.ts`：现有默认模式已经是 daemon，代理尚未选择；
  默认配置开启 metrics/content 遥测。个人版需明确首次代理选择及旧配置迁移。
- `apps/daemon/src/server.ts`：启动时初始化 AMR endpoint binding，构造协作云客户端，
  启动协作云服务和发布 watcher。须逐项核对启动副作用及其所有调用方。
- `apps/daemon/src/app-config.ts`：无遥测配置时会补上开启值。仅修改前端默认值
  无法保证后台停止上报，也无法迁移已经保存的开启值。
- `apps/daemon/src/cli.ts`：已有工作区、计费、分享命令。删除云能力时同步清理
  CLI 命令和帮助；本地项目能力仍复用同一 HTTP API。

这些是初步入口盘点，不代表已经穷尽依赖或证明当前本地流程可用。

## 交付顺序

### 1. 建立可重复的本地基线

安装锁文件指定的依赖；使用 `pnpm tools-dev` 启动独立验证环境。
daemon 数据目录严格遵循根 `AGENTS.md` 的 Daemon data directory contract。
不改动既有用户数据，不用删除数据库或伪造云身份来绕过权限。

无官方登录，选择本地 CLI，验证创建原型、修改、保存、重启恢复和本地导出。
记录基线故障，区分原有问题与裁剪回归。测试代理可使用仓库 mock；
真实模型生成另外记录为人工验收，避免把 mock 成功等同真实模型可用。

### 2. 让本地流程独立

将项目创建、读取、修改、删除、历史恢复和导出固定到本地持久化路径。
核对前端工作区请求上下文、daemon 权限和项目所属关系，保持对已有云项目的
明确隔离；不把旧团队项目自动降级为本地项目。

首次启动直接进入本地代理选择；已有有效的非 AMR 配置继续生效。
旧 AMR 默认选择需要显式重新选择本地代理，不能任意改写为某个未安装 CLI。
自定义 API 的密钥和配置继续遵守现有凭据保护边界。

### 3. 移除官方云链路

同时清理前端入口、后台请求、轮询、启动服务、HTTP 路由、CLI 命令、
配置项与对应测试。停止官方遥测的采集和上传，包括旧配置迁移；
保留本地诊断能力。不要用一个可恢复官方功能的隐藏开关代替最终代码裁剪。

本地服务 token、请求来源检查、路径授权、预览隔离和文件读写限制继续保留。
用户配置的代理/API 外网访问属于生成能力，不能被误当成官方云请求整体禁用。

### 4. 回归与清理

每个改动运行对应的聚焦测试；按根规范运行 guard 和 typecheck。
不在本地运行完整 daemon/web 测试集。只有调用方全部清除后再删除模块与依赖。
依赖或工作区入口变化后重新执行 pnpm install。

## 完成标准

- 无官方账号、无官方云服务时，UI 与 CLI 都能完成本地项目生命周期。
- Codex、Claude Code 等本地代理通过现有适配器工作；不要求安装全部代理。
- 模型失败时显示本地代理或自有 API 的实际错误，不引导官方登录或充值。
- 修改后的 HTML、资源和历史记录在重启后可恢复，导出产物可在本地打开。
- 正常启动和项目操作不发起官方登录、计费、团队、同步、分享或遥测请求。
- 模板、设计体系、技能、预览及 HTML 编辑保留；本地接口安全检查继续生效。
